# Vikix: programs

A page of the Vikix skill (~/.claude/skills/vikix/SKILL.md: read that first, its rules hold here). The programs Vikix brings and the commands around them: files, screenshots, passwords, web apps, plugins, Windows programs, slides, books, lessons.

## Files

- Esploro (Super+e; PCManFM where it isn't installed, and on Super+Alt+e always): the feature `esploro`, which needs emacs: Vid's file explorer, github.com/vukini/esploro; its window is an Emacs frame titled Esploro, on dired, with menus, a tool bar, right-click menus, drag and drop; its core, the `esploro` command built with SBCL from a pinned commit into ~/.local/opt/esploro by `vikix esploro setup|status|doctor|uninstall`, does every change as a journaled plan (`esploro apply`, `esploro undo`) and knows which window has each file open, over this Swank; `esploro FOLDER` opens it through emacsclient, loading ~/.local/opt/esploro/emacs/esploro.el the first time, in the Esploro frame on the current workspace (it asks StumpWM) or a new one there; `esploro --new FOLDER` always a new one (Super+Alt+Shift+e); F3 two panes, F11 a preview; Super+Alt+r (`esploro reveal`) the file behind the focused window; Super+Alt+x (`vikix-esploro menu`) Esploro's file commands for it, in rofi; when the user speaks of "the files I've selected", `esploro selection` prints them (selected in the Esploro view, or dired, used last), one a line; `esploro query --lines WORDS FOLDER` finds files (words a name holds, `*.pdf`, `kind:pdf`, `newer:7`, `larger:10M`, `-word`); a new Esploro opens in the workspace's project; to change the user's files, files can carry the user's tags (words of their own, kept on the file in `user.xdg.tags`; `esploro tags of FILE...` reads them, `esploro query --lines tag:NAME FOLDER` finds by one, and a plan step `tag` sets them: propose it, never `setfattr`); look first at what was already done with the read-only MCP tool file_changes (Esploro's changes, newest first, in words: "what did I move yesterday?"); propose them with the MCP tool propose_file_changes (shown in Esploro, applied only by the user, undoable) rather than moving them yourself, following the user's rules for where their files go in `~/.config/esploro/sorting.md` (theirs; the tool's description carries them; when they correct a plan, offer to add the correction there); folders (inode/directory, set over PCManFM only), drives (udiskie opens them with xdg-open) and the browsers' "Show in folder" (org.freedesktop.FileManager1, a D-Bus service file in ~/.local/share/dbus-1/services running `esploro --dbus`) open in it; each frame and pane keeps its own folder and history; its manual is `info esploro`, ? in it.

## Small tools

- Super+c clipboard history (clipmenu), Super+. emoji picker and Super+= calculator (vikix-rofi: rofi-emoji, rofi-calc with qalculate; Enter copies the answer).
- Screenshots and recording: Print a screenshot of an area (or a clicked window), Ctrl+Print of the focused window, Super+Print of the monitor under the pointer, all to the clipboard (vikix-screenshot; add Shift for a file in ~/Pictures/Screenshots), Super+Ctrl+v record an area or window and again to stop (vikix-record, ffmpeg, no sound; the bar says rec; videos in ~/Videos/Recordings), Super+Ctrl+Print a menu of all of them (also `vikix-screenshot text`: an area's text by OCR, tesseract, to the clipboard, VIKIX_OCR_LANG for other languages; `vikix-screenshot colour`: xcolor, the #rrggbb to the clipboard).
- Passwords: Super+Alt+v (`vikix bitwarden pick`, the feature bitwarden: rbw + rofi-rbw, the user's Bitwarden vault; Enter types username Tab password, Alt+3 the password alone; never read or print the user's vault yourself, and never ask for the master password: it goes only into pinentry's box.
- Dropbox and the Apps menu: Super+m → Apps → Dropbox has status, start and stop; Super+m → Apps lists, with Dropbox, the Windows VM and the web apps, the programs of the features video, graphics, blender, study, passwords, bitwarden, phone and cli-extras that are installed (`*vikix-apps-menu*`). Vikix never starts Dropbox itself.
- Web apps: `vikix webapp add NAME [URL] [--key s-M-X]` (presets superhuman, fastmail, gmail, outlook, outlook-live, and the meeting ones teams, meet, zoom, which start with the camera and microphone allowed for their site; `--media` / `vikix webapp media NAME on|off` for others, written into the profile's Preferences as it starts; the first mail one gets `s-M-m`) makes a Chromium app window with its own class (vikix-NAME) and profile (~/.local/share/vikix/webapps/NAME, logins apart); the list is the user's ~/.config/vikix/webapps (NAME URL [KEY]); webapps.lisp binds the keys (run-or-raise by class) and adds Super+m entries; `(vikix-load-webapps)` re-reads it. `vikix webapp key NAME KEY|none` moves or drops a key (always Super with Alt and a letter, digit or F-key, `s-M-k`; never one of Vikix's own); `vikix webapp list/remove [--forget]` (remove keeps the logins; --forget deletes them). Notifications only while the window is open; to start one at login: `(run-shell-command "vikix-webapp launch NAME")` in user.lisp.

## Plugins and what they find

- Plugins (`vikix plugin list|add|remove|off|on|safe|status`): from github.com/vukini/vikix-plugins at the commit pinned in bin/vikix-plugin, in ~/.local/share/vikix/plugins (Vikix's: don't edit), the user's list ~/.config/vikix/plugins.list and settings ~/.config/vikix/plugins/NAME (theirs); agent-waiting adds Claude Code hooks (Notification, Stop, UserPromptSubmit) that run agent-waiting ask|done|clear, notes in ~/.local/state/vikix/agents/, the bar's `agent asks`, Super+Alt+w goes to the window; ai-usage makes Claude Code's statusLine ai-usage-statusline (notes rate_limits in ~/.local/state/vikix/ai-usage; Super+Alt+u); next-meeting reads the user's private calendar links (~/.config/vikix/plugins/next-meeting/calendars, 600: secrets, never print or read them out) every 5 minutes (next-meeting watch, a plugin service) into ~/.local/state/vikix/next-meeting, Super+Alt+j joins, Super+Alt+c lists the week; inbox (Super+Alt+i) captures a note into the user's Org inbox (~/Dropbox/notes/inbox.org, the user's file: add to it only when asked, `inbox add TEXT`; `inbox sort` moves notes into the .org files beside it, only when the user runs it, copies kept for `inbox sort --undo`; in Emacs, ~/.local/share/vikix/emacs/vikix-notes.el puts the notes under C-c n: agenda, TODOs, journal, org-roam links and graph; `vikix obsidian convert FOLDER` turns an Obsidian vault into Org notes in ~/Dropbox/notes/vault, the vault only read: convert only when the user asks); a plugin hanging the desktop: `vikix plugin safe`, log in, `vikix plugin off NAME`.
- The record store (`vikix records search|list|get|export|forget|stats`, ~/.local/share/vikix/records.db, SQLite with full-text search): what plugins found (flight searches and prices, meetings joined, Claude plan use); read it through the MCP tools records_search / records_get or the command; don't write or forget records unless the user asks.

## Bigger things

- Windows programs in their own windows: `vikix windows apps setup` (once, in a terminal: FreeRDP, RemoteApp on through the guest agent, the password kept in secrets/windows-password, never exported), `vikix windows apps` (the Start menu), `apps add NAME` (a launcher entry), `vikix windows app NAME [FILE]` (RemoteApp through xfreerdp3, the password on stdin; files only from ~/Windows = Z: and ~/Documents = Y:); windows have the class `vikix-win-NAME`. The VM takes 6 GB: don't start it without asking.
- Windows VM (the feature `windows`): `vikix windows setup` once (records the feature, so 10-packages installs `packages/optional/windows.list` now and at every update; `vikix add windows` runs the same), `vikix windows create ISO [--key KEY]` (unattended: answer file from lib/windows-unattend.py on a disc it deletes when done), then `vikix windows` / `stop` / `status` / `remove`. It is libvirt's qemu:///session, so always `virsh -c qemu:///session` (the system libvirt won't see it); its network is the system libvirt's NAT bridge virbr0 (through qemu-bridge-helper and /etc/qemu/bridge.conf), so Windows can't reach this machine's 127.0.0.1 services; `vikix windows network` fixes a VM still on passt, `vikix windows status` or `vikix doctor` show which network it's on (a VM moved while running needs a restart); the VM is named `windows`, its disk in `~/.local/share/libvirt/images/`, `~/Windows` is drive Z: (virtiofs). Never read or print the answer disc (it holds the Windows password); `remove` deletes the VM's disk, so only when the user asks.
- Slides: Hype (the feature `hype`; `vikix hype setup|status|uninstall`): DHH's Markdown presentation app, built from a pinned release into ~/.local/opt/hype; `hype new FILE.md --theme NAME`, `hype open`, `hype check`, `hype render`, `hype export FILE.md out.pdf|.pptx`, `hype help format` for the Markdown. Its window follows `vikix theme` (written in Omarchy's form to ~/.local/state/omarchy/current/theme/colors.toml), and every Vikix theme is a slide theme (~/.local/share/vikix/omarchy/themes, the `hype` command's OMARCHY_PATH). Open/Save use xdg-desktop-portal with gtk (~/.config/xdg-desktop-portal/portals.conf). Setup installs Hype's own skill (~/.claude/skills/hype): when asked for a talk or slides, use it.
- Books: the feature `publish` (`vikix publish [NAME|DIR] [epub|pdf|check]`, `setup|status|uninstall`): a folder with `publish.yml` (pandoc metadata plus `name`, `chapters`, `mainfont`) and `chapters/*.md` or `book.md` becomes `out/NAME.epub` (pandoc, tables turned into row cards for e-ink readers, epubcheck) and `out/NAME.pdf` (Typst; IBM Plex Serif, Arabic in Amiri). A rejected build is `NAME.epub.rejected` or `NAME.pdf.rejected`, never the book. `vikix publish NAME check` is the gate before saying a book is done. A project's Makefile gets `make epub/pdf/check` from `-include $(HOME)/.local/share/vikix/publish/publish.mk`. Spelling: `vikix publish NAME spell` lists unknown words by chapter (the book's `lang`, British for English; `::: {lang=eo}` passages in their own; code skipped); real terms go in `words.txt` (`spell --keep` adds them all, then remove the true typos from it). `vikix publish NAME --send` puts the EPUB on the reader plugged in (Kindle/Kobo drive, BOOX over MTP or adb), `--to FOLDER` elsewhere. A new book: `vikix publish new DIR [--title T] [--lang L]` (publish.yml, chapters/01-start.md, words.txt, the Makefile line; never over a book). `vikix publish skill` writes the claude.ai `doc-to-epub` skill as ~/Downloads/doc-to-epub.zip from the same files, for the user to upload; a .docx is a book's text through `chapters: [../INPUT.docx]`. In a git repository `spell --keep` commits the book's `words.txt` and `new` a book's first files, those files alone (a file with changes waiting is left, and said; `--no-commit` leaves git alone): `words.txt` is the book's own, to be committed with it, never ignored.
- Learning: `vikix learn c` (bin/vikix-learn, language-neutral; the course in the checkout's `learn/c/`): lessons copied once to `~/learn/c/NN-name/` (the user's files, in yours.list), each with lesson.md, example.c and exercise.c ending in a `// NOT DONE` line; the checks (`learn/c/NN/check.sh`, with `learn/c/lib.sh`) stay Vikix's and build with -std=c17 -Wall -Wextra -pedantic -Werror under ASan and UBSan (libsanitizer-devel, in dev.list); `vikix learn c` (Super+m → Learn C, the StumpWM command vikix-learn-open in commands.lisp) opens the first empty workspace split in two: the lesson pane (lib/learn-view.py, curses: n/p next and back, h hint, c check, r reset, q closes both and returns) and a shell in the lesson's folder that follows it at each prompt; `next`, `prev`, `list`, `hint`, `go NN`, `check`, `reset NN`, `--here`; progress, the lesson and the place in it, in ~/.local/state/vikix/learn/c. When helping a learner: explain the failing step and give a hint, and write the full answer only when asked.
