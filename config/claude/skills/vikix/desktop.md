# Vikix: the desktop

A page of the Vikix skill (~/.claude/skills/vikix/SKILL.md: read that first, its rules hold here). What Vikix defines in StumpWM, for use in the user's `~/.stumpwm.d/user.lisp`: commands, keys and the menu, the bar, windows, strips, the drawer, layouts, the look.

## Commands, keys and the menu

- `(vikix-bind "s-KEY" "command")` binds a Super key (`s-` Super, `C-` Ctrl, `M-` Alt; `s-H` means Super+Shift+h). Commands are StumpWM command strings: `"exec firefox"`, `"vikix-terminal"`, `"move-focus left"`.
- A command of the user's own, with its key and its place in Super+m, is one form in user.lisp, as Vikix writes its own (`registry.lisp`): `(define-vikix-command obsidian "Obsidian: my notes" :run "exec obsidian" :key "s-M-o" :menu "Apps" :needs "obsidian")`. The name is theirs to choose; the words are what the key card (Super+/), the key help (Super+F1) and the menu say; `:run` is a StumpWM command string and `:key` its key; `:menu` is one of Start, Help, Vikix, AI, Work, Notifications, Desktop, Windows, System, Apps (without it: a key alone); `:label` the menu's own words; `:needs` a program on PATH or a file (`"~/..."`) without which the menu leaves it out; `:do FORM` in place of `:run` for a menu entry with no key; `:agent t` lets agents run it by name (only a switch or a move, never one that asks a question or starts a program). A mistake in the form is said as user.lisp loads. `*vikix-bindings*` is still the list of keys the card and the help are built from, `(key command description [group])`: the older way, `(push '("s-y" "exec xterm" "XTerm") *vikix-bindings*)` then `(vikix-bind "s-y" "exec xterm")`, works too.
- `(setf *vikix-terminal* "xterm")` changes the terminal Super+Return opens.
- `*vikix-menu*` is the Super+m menu: a list of `(label action [needs [section]])`, where the action is a command symbol or a Lisp form, needs a program on PATH or a file (`"~/..."`, `nil` for nothing) and section the part of the menu it is in (`"Work"`; none: a section called Yours). Vikix's entries come from `registry.lisp`; add one with `define-vikix-command ... :menu`, or with `push` or `append` to the list in user.lisp. The menu opens on its sections (Start, Help, Vikix, AI, Work, Notifications, Desktop, Windows, System, Apps, a plugin's own, Plugins, Yours, Power), each row saying what it holds; Enter or Right opens one, Escape or Left comes back; typing at the top finds an entry of any section; a section of one entry is that entry, at the top; each entry shows its key. So "Super+m → Printers" means: Super+m, then type `printers` (or open System).
- Commands are defined with `(defcommand name (args) (prompts) "doc" body)`; `(documentation 'name 'function)` shows a command's description.
- `(vikix-in-terminal "shell command")` runs a command in a terminal that waits for Enter.
- `(run-shell-command "program")` starts a program now. A program to start with the desktop is a rule, `(at-login (run "program"))`, in rules.lisp or user.lisp: it runs once a login, not at each reload (a bare `run-shell-command` in user.lisp starts another copy at every reload).
- **The rule for keys** (keys.lisp; the user's guide: customize, "The rule for keys"). Each modifier beside Super means one thing, and a key you add for the user keeps to it. **Super alone:** everyday (the six main apps: terminal, launcher, browser, files, editor, agent; the small tools; focus; what is done to the window). **Super with Shift:** the same key moving the window (move, send to a workspace, bring here) or its other way (redo, previous). **Super with Alt:** open something else (every other app, web app and plugin: a new app's key is `s-M-LETTER`). **Super with Ctrl:** switch something on the desktop (a toggle of the user's: `s-C-LETTER`). Print and the laptop's own keys keep their own ways. Before giving a key, check it's free: `vikix eval '(lookup-key *top-map* (kbd "s-M-o"))'`. `vikix doctor` names keys that break the rule; `vikix eval '(vikix-key-problems)'` lists them. A command of the user's that is a switch: `(push "my-toggle" *vikix-key-switches*)` in user.lisp. Super with Shift and a digit sends a window to that workspace on any keyboard layout (Vikix asks the keyboard what Shift and the digit type).
- Every key as installed, and the commands an agent may run by name: `~/.claude/skills/vikix/keys.md`.
- StumpWM's own keys follow the prefix Ctrl+t; which-key-mode is on (help.lisp sets it with `(vikix-which-key t)`, `nil` turns it off; never call the toggle `(which-key-mode)` from user.lisp, as each reload would flip it). Focus follows the mouse (sloppy focus).

## The bar, notifications and small switches

- The bar takes clicks: a workspace's number goes there, a window's title focuses it, vol opens pavucontrol (wheel up/down, middle mutes), the network `vikix wifi` (the picker: a scan first, then the list; `vikix wifi list` prints it; a cable opens nmtui), bt blueman (modeline.lisp, vikix-ml-clickable; the narrowest overlapping area wins).
- What the bar says: `quiet` (do not disturb), `focus 24` / `break 5` (focus time, Super+m Notifications, no key: `vikix-focus-time [MINUTES|off]`, do not disturb on by itself meanwhile; `*vikix-focus-minutes*`, `*vikix-focus-break*`), `awake` (keep awake), `rec` (a recording runs), `mic` (dictation listens), `usb` (a drive is mounted), `ai` (a local model is loaded), `updates N` / `Vikix update`, `backup 9d`, `mem 91%` / `left 5`, `agent asks`; the bar also shows `bt`, or `bt DEVICE 80%`, while Bluetooth is on, from bin/vikix-bt, and `dbx ↓N` / `dbx off` / `dbx !` for Dropbox, from bin/vikix-dropbox, with the feature dropbox.
- Notifications: Super+n / Super+Shift+n the last notification again / pick an earlier one, Super+Ctrl+n close all, Super+Ctrl+d do not disturb (dunstctl; the bar says quiet).
- Super+Ctrl+a keep awake (vikix-idle; no lock, dark screen or suspend; the bar says awake). Super+Ctrl+l night light on/off (vikix-nightlight, gammastep; times and colours in the user's ~/.config/gammastep/config.ini; off lasts across logins).
- A reload (`vikix eval '(loadrc)'`, Super+m Reload config) loads Vikix's files from compiled copies (`~/.cache/vikix/fasl/`, made in the background after a file changes) and the user's files from their text: well under a second, about two more right after an update. `vikix times files` shows the last load file by file. The bar's values come from a thread of their own (`vikix-bar`); a field of the user's own in the bar should read a variable, with whatever asks a program run from `*vikix-bar-refreshers*` (push a function that sets the variable and calls `vikix-bar-redraw`), never from the mode line's formatter, which runs in StumpWM's main thread.

## Windows

- Dialogs (transient, modal, or of a class in *vikix-dialog-classes*: zenity, polkit, ssh-askpass, pinentry ...) float centred and are raised again whenever focus moves, so they stay in front (windows.lisp).
- Super+o every workspace drawn small on a card, to pick a window (`g` there: this workspace in a real grid, StumpWM's expose, which Super+u undoes).
- Super+Shift+o grid mode on/off (`vikix-grid` in windows.lisp: the workspace re-tiles into the grid as windows open and close; floating windows and dialogs stay out).
- Super+Ctrl+m main and stack mode on/off (`vikix-main [on|off]` in windows.lisp; what dwm calls master and stack: the focused window down the left, three fifths wide, the others in a column on its right, kept so as windows open and close; a new window opens at the top of the stack, or as the main one with `(setf *vikix-main-new* :main)` in user.lisp; in the mode Super+Shift+h/j/k/l swap the window with the one that way, so Super+Shift+h makes it the main one, and Super+r goes through the main window's widths, `*vikix-main-shares*`; the stack shows `*vikix-main-stack-max*` windows, 4; a workspace always so: the rule `(when-workspace 2 (command "vikix-main on"))`; `(vikix-main-p)` says whether a workspace is in it; grid mode and this one are never both on).
- Super+Ctrl+Space the layout keys, a map (`vikix-map layout` in help.lisp: a card of single keys that act while it shows, half a minute after each (`*vikix-map-timeout*`): `m` main and stack, `s` strip, `g` grid, `t` tiles, `w` width, `h` height, `u`/`r` undo/redo, Space the layout picker; Escape or the key again closes it). The picker is `vikix-layout-pick [tiles|main|grid|strip]` in layouts.lisp: a menu of those four and of the saved layouts, opening on the current one; with a name it switches straight to it, so a key or a rule can; `(vikix-layout-now)` gives `:tiles`, `:main`, `:grid`, `:strip` or nil. Super+Alt+d is the desks' map (`n` new, `r` resume, `c` close, `h` handoff, `o` the Office). A key inside a map is written in the registry as `:map "layout x"` beside or instead of `:key`, and reads `Super+Ctrl+Space, x` in keys.md.
- Super+z focus (only this window; Super+z again restores the workspace's layout exactly: `vikix-solo` in windows.lisp, per workspace, StumpWM's dump-group/restore-group, floating dialogs left alone). Super+u / Super+Shift+u undo / redo a layout change, Super+Ctrl+g gaps on/off.
- Super+g / Super+Shift+g any window on any workspace (go there / bring it here; `vikix-go-to-window` and `vikix-bring-window` in windows.lisp: each line of the list has the window's workspace, its title and what it is, for a terminal its folder and what runs in it; windows on a hidden workspace are left out).
- Super+t float the focused window or tile it again (`vikix-float`), Super+Ctrl+y title bars on/off (windows.lisp: a strip at the top of each tiled window with its number and name, drawn by wrapping maximize-window, and of each column's window on a Viri workspace, placed by `viri-layout`; a fullscreen window has none; off is `~/.config/vikix/titlebars-off`), Super+" rename the window (`vikix-title`), Super+p pointer to the focused window.
- A whole workspace's windows, brought here: Super+m → Windows → *Bring every window of another workspace here* (the StumpWM command `vikix-gather`, or `vikix-gather 2` for workspace 2; from a shell, `vikix eval '(vikix-gather "2")'`). They arrive as ordinary windows: tiles on a tiled workspace, columns on a strip; a strip's windows and ones that floated no longer float, but a dialog and a window a rule floats stay afloat. Use it, not StumpWM's `gmerge`, which moves windows as they are. A rule's `(dialog)` lasts only while its window floats and is never a strip's column.

## Strips, the drawer, layouts, resume

- Strips (Viri, `viri.lisp`): `vikix viri [on|off]` (or the StumpWM command `vikix-viri`) turns the current workspace into a strip of half-screen columns that scrolls sideways, keeping its windows in order, or back into tiles split as they were before. On a strip, Super+h/l (`vikix-focus`) walk along it and Super+Shift+h/l (`vikix-move`) move a column; elsewhere those commands are `move-focus` / `move-window`. Dialogs float in the middle. The bar's window list (%W) shows the strip in order, the columns on screen in [brackets]; the focused column has the accent border. Super+Home / Super+End (`vikix-focus-end first|last`) go to a strip's first and last column (`vikix-move-end first|last`, no key, moves the column there). Super+\ (`vikix-pin [on|off]`) pins the focused column to the screen's left edge, where it stays while the others scroll beside it (one a strip, `(viri-pinned group)`; it is the first of `viri-cols`; the bar writes `D | A [B C]`; a saved layout keeps it as `:pinned t`). Super+z on a strip (`vikix-solo` there calls `viri-toggle-tabs`) makes the focused column's windows tabs: one shown as high as the column, the others hidden behind it (`window-hidden-p`), each a cell in the title bar; Super+j/k go between them, a click on a tab too; the bar writes `D+E+C`; `(viri-tabbed-p col)`; a saved layout keeps it as `:tabbed t`. Sending a window to a workspace is `vikix-send N` (StumpWM's `gmove`, and on a strip the whole column the window is in: one column there on another strip, with its width, tabs and heights; tiled on a tiled workspace). Super+b on a strip (`vikix-split` there, or the command `vikix-fill`) makes the focused column as wide as the room the other columns wholly on the screen leave, so that together they fill it. Super+v on a strip (`vikix-split below` there, or the command `vikix-height`) makes the focused window taller in its column: the next of `*viri-height-shares*` (1/3 1/2 2/3) above what it has, then every window even again; the edge between two stacked windows drags; `(viri-height-share col window)`; weights in `*viri-weights*`, 1 an even share; a saved layout keeps them as `:heights`. Touchpad sweeps (`bin/vikix-gestures`, started by vikix-session; `vikix gestures [on|off]`): three fingers swept left, right, up or down run `vikix-focus`, a step for each `distance` of the sweep (120 as it comes), in the direction the touchpad scrolls (`natural` not said: the focus goes the way the fingers do where natural scrolling is off, as on the user's machine, whose `user.lisp` turns it off); it hears XInput 2.4's swipe events on the root window through libX11 and libXi, so it needs no `input` group; settings in the user's `~/.config/vikix/gestures` (`fingers`, `distance`, `natural`; `vikix gestures on` starts the listener again so that they apply), off while `~/.config/vikix/gestures-off` exists. Two fingers swept sideways over a strip walk along it too, without the listener: the touchpad's sideways scrolling comes to StumpWM as buttons 6 and 7, and `viri-scroll-walk` makes every `*viri-scroll-clicks*` (6) of them a step, unless the sweep is mostly up and down; `*viri-scroll-walks*` nil leaves sideways scrolling to the programs. The mouse on a strip (`group-button-press` for `viri-group`): Super and the wheel walk along it, as the wheel on the bar's window names does; a drag of a title bar (or Super and a drag) carries the column to where it's let go; a drag of a column's side edge (or Super and a drag with the right button) changes its width by `*viri-width-step*`, a twentieth of the screen, so a width can be any such fraction, not only the four Super+r goes through; a click on a box of the overview goes to its window. Scrolling to a column leaves `*viri-peek*` pixels (24; 0 for none) of the next column in sight at each edge that has one. The strip slides as it scrolls when a compositor runs (`*viri-animate*`: t, `:always` or nil; `*viri-animate-seconds*` 0.12, made of sleeps in the main thread, never a timer), and `(setf *viri-centre* t)` in user.lisp keeps the focused column in the middle. A strip is a `viri-group` (a float group whose windows Viri places): `(viri-group-p)`, `(viri-columns (current-group))`. Super+r (`vikix-width-or-remove`) cycles the focused column through `*viri-widths*` (1/3 1/2 2/3 1; `remove` on tiles). A strip is a list of columns (`(viri-cols group)`, each a `viri-col`: windows top to bottom, width, last focus), scrolled by `viri-offset` pixels; `(viri-columns group)` is every window in order. Super+[ / Super+] (`vikix-stack left|right`): the window joins the column that way, at its bottom, or leaves a shared column for one of its own that way; Super+j/k move up and down a column, with Shift they move the window; a column's windows share its height. Super+o (`vikix-overview`, `overview.lisp`) draws every workspace that has windows small on one card: tiles as their frames (a frame's windows behind the one it shows are lines in its box), a strip as its columns with a line around what's on the screen; each window a box with its number, name and what it is; arrows or h/j/k/l move a frame, across workspaces too, Enter or a click goes there, a digit goes to that number on the frame's workspace, `/` is Super+g's list, `g` is `vikix-expose` (StumpWM's expose: this workspace in a real grid, tiles only), any other key closes; while it shows the keyboard is grabbed and `*vikix-overview*` is non-nil (its `:plan` holds the panels and boxes), so don't send keys meant for a window then. The MCP `desktop` tool gives each workspace's `kind` (tiles, strip, floating) and, for a strip, its `columns` left to right (width, window numbers top to bottom, `on_screen`).
- The drawer (`drawer.lisp`, Super+Ctrl+b, the StumpWM command `vikix-drawer [on|off]`): a few everyday programs in a column at the screen's edge, floating over the windows of whatever workspace the user is on; the key again puts them away, still running, on the hidden workspace `.drawer`. Its programs are the user's list in `user.lisp`, top to bottom: `(setf *vikix-drawer-apps* '(("Calculator" "speedcrunch") ("Notes" "emacsclient -c -n -a '' -F '((name . \"Notes\"))' ~/notes.org" :class "Emacs" :title "Notes")))`: a name, a shell command, and, only for a window another process makes (an Emacs frame, a second PCManFM window), how to know it, as a rule's matchers. `*vikix-drawer-side*` is `:right` or `:left`, `*vikix-drawer-width*` `"30%"` or pixels. `(vikix-drawer-windows)` lists its windows, `(vikix-drawer-window-p WINDOW)` asks of one. A window the drawer started is the drawer's whatever the user's rules say of that program (it takes it after the rules ran). Don't move a window to `.drawer` yourself or float one at the screen's very edge by hand.
- Saved layouts (`layouts.lisp`): `vikix layout save NAME`, `vikix layout NAME` (put back), `vikix layout list|rm NAME`; files of plain Lisp in `~/.config/vikix/layouts/NAME.lisp` (the user's; in the snapshot history): `(:layout "NAME" :kind :tiles [:mode :main|:grid, when saved in main and stack or grid mode, which it comes back in] :current N :tree ((:frame N :x 0.5 :y 0.0 :width 0.5 :height 1.0 :windows ((:class .. :instance .. :title ..)) :shown (...))))` or `:kind :strip :columns ((:width 2/3 :windows (...)))`. Windows are matched by class (or instance), then title; parts of the screen are of the whole screen, the bar's strip included. Restoring a strip's layout makes the workspace a strip, and the other way; unknown windows stay; missing ones are started again from their saved `:command` (in `:directory`) and placed as they come, unless `--no-start` (`:start nil` in Lisp); one just started isn't started again for 30 s. A terminal is saved as itself in its shell's folder (plus `-e` what ran in it, if not a shell), an Emacs frame as `emacsclient -c -n -a "" FILE` (asked of Emacs), Esploro as `esploro --new FOLDER`. In Lisp: `(vikix-layout-save "NAME")`, `(vikix-layout-restore "NAME")` (returns the missing ones).
- Resume (`resume.lisp`, `vikix resume [now|save|ask|always|never]`, Super+m Bring my windows back): the desktop saves every workspace as a layout every five minutes and at its end, in `~/.local/state/vikix/resume/` (workspace-N.lisp, index.lisp; Vikix's, don't edit), and after a restart a login asks (the user's `~/.config/vikix/resume`: ask, always or never) whether to bring the windows back: each workspace in turn, its programs started again in their folders. `vikix eval '(vikix-resume-summary)'` says what is saved. Only what can be started again comes back (a terminal in its folder with its program, a command line, a web app, an Emacs frame); tell the user before running `vikix resume now` on a desktop that has windows: it switches through the workspaces.

## Finding things, and what happened

- The palette (Super+Space, `bin/vikix-palette`; `vikix-palette --list` prints what it offers): one launcher box over the user's windows on every workspace, every registered command with its key, their projects, web apps, saved layouts and the programs. A command you add to the registry (`define-vikix-command` in user.lisp) is in it at once; nothing else needs listing. Super+d stays the plain launcher.
- What gets used (`used.lisp`, `vikix used [never|all|forget]`, Super+m What you use): the desktop counts each key that runs a command (with the command), each menu entry, palette pick, typed command (its name only), rule and agent's command, in `~/.local/state/vikix/used` (tab-parted: kind, count, first, last, what; written every five minutes and at the desktop's end). Names and counts only, never a window's title; it stays on the machine. `vikix used never` lists the keys never pressed: read it before proposing to move or drop a key of the user's, and don't delete the file (`vikix used forget` is theirs to run).
- Why something happened (`why.lisp`, Super+?, `vikix why [N]`, the MCP tool `why`): the desktop keeps the last fifty things it did, each with what made it happen and where that is written: a key and the command it ran ("Vikix's key: registry.lisp, line 83", "your key: user.lisp, line 242"), a rule and the window it ran for, an entry of Super+m, a command an agent ran, the last notification and its program, a command "asked for" (a click on the bar, a script, vikix eval). When the user says a window moved by itself or a key did something odd, read `vikix why` first, before guessing; `vikix rules why CLASS` then says more about one window. Super+? shows the list on the desktop and offers, for the one picked: edit its line in Emacs, take it back (a switch run again, a layout change undone), bring a moved window here, switch a rule off.
- What a thing is (`what.lisp`, Super+Alt+?, `vikix what [KIND] [NAME]`): a card for a field of the bar, a window, a workspace, a key, a running process or a package, with what that very thing is doing now (read a moment ago: a process's memory, parent, ports and package; where a key is written and how often it is pressed; what a field shows), a short paragraph on what such a thing is, and where to read on. `vikix what NAME --json` is the card as data, and a quick way to learn about a process or a key before answering a question on it. The paragraphs are Vikix's pages, `config/what/KIND.md` (Vikix's, not the user's to edit): they name Vikix's guides, manual pages and its own files only. The user's own pages (`what=` in `~/.config/vikix/docs`) may add a paragraph and `chapter:` lines to their own documents; never write those pages or that file for the user, and never put the user's documents into Vikix's.

## The look

- Themes: `vikix theme NAME` (shell) switches everything (StumpWM, terminals, rofi, dunst, lock screen) and saves the choice; `vikix theme` lists them; built in: vikix-dark (default), vikix-light, gruvbox-dark, nord-dark, tokyo-night-dark, contrast-dark (high contrast, 7:1); every name ends in -light or -dark, and the old names (void, paper, gruvbox, nord, tokyo-night, contrast) still switch, to the new one. The editors follow too, at once in a running Emacs and every Neovim: Neovim's `lua/vikix/theme.lua` (Catppuccin, gruvbox.nvim, nord.nvim, tokyonight.nvim; any other theme the scheme `vikix`, mini.base16 from `~/.config/vikix/theme/palette`), Emacs's `vikix-theme.el` (Catppuccin and doom-themes from MELPA when first needed, modus-vivendi for contrast-dark, `vikix-palette` for the rest; `M-x vikix-theme-apply` re-applies). A user keeps their own colours with an astroui `colorscheme` spec in `~/.config/nvim/lua/plugins/`, or by not loading vikix-theme.el. A theme is a file of colours: `themes/NAME.theme` in the checkout, or the user's own in `~/.config/vikix/themes/NAME.theme` (copy `vikix-dark.theme` and change it; the name must be letters, digits, `-` and `_`, or the file is neither listed nor used). `vikix theme import OWNER/REPO|https-URL [NAME] [--force] [--no-switch]` makes one of the user's own from an Omarchy theme repository: its `colors.toml` colours (read as data, only `#rrggbb`) and the first picture in `backgrounds/` go into `~/.config/vikix/themes/NAME.theme` and `NAME.jpg|png|webp`, then it switches (not with `--no-switch`). The name defaults to the repo's without `omarchy-`/`-theme`; it won't replace a user theme without `--force` (old files kept as `.vikix-bak`), nor take a built-in's name. Use `--no-switch` if the user only asked to import. Programs get the colours from files `vikix theme` writes into `~/.config/vikix/theme/`, which their configs include; don't edit those, they're overwritten. `(vikix-apply-theme :name)` in Lisp repaints StumpWM alone. The wallpaper: `vikix-wallpaper` (pick, FILE, cycle [MINUTES], next, theme, off, which); by default it cycles (a new picture every 30 minutes, `~/.config/vikix/wallpaper-minutes`, from the collection, `~/Pictures/Wallpapers` and `~/wallpapers`, never the themes' own: every picture once in a shuffled order before any comes again, one added to a folder shown next; the one showing is in `~/.local/state/vikix/wallpaper-now`, the round in `wallpaper-queue` and `wallpaper-shown` beside it; `vikix-wallpaper --watch`, started by vikix-session, changes it), and `~/.config/vikix/wallpaper-theme` means it follows the theme instead; a fresh install adds the feature `wallpapers`; the picker lists the themes' pictures, `~/Pictures/Wallpapers`, `~/wallpapers` and, with the feature `wallpapers` (`vikix wallpapers setup|update|status|uninstall`), Vid's collection cloned into `~/.local/share/vikix/wallpapers` and pulled by `vikix update`; `~/.config/vikix/wallpaper-off` means the user sets it with their own tool (feh, nitrogen, a rotator in user.lisp) and Vikix never touches it; the user's choice is the link `~/.config/vikix/wallpaper`; following the theme, its picture beside its theme file (themes/vikix-dark.jpg), otherwise a plain background in the theme's bg (also when there's nothing to cycle). `vikix theme NAME` applies it too; `vikix update` doesn't. StumpWM's bar, menus and messages are in Iosevka through the contrib module ttf-fonts: `bin/vikix-font` makes `~/.local/share/vikix/fonts/wm.ttf` (Iosevka Regular out of Void's .ttc, or a link to Noto Sans Mono), and theme.lisp loads only that folder. Never run the module's `cache-fonts` over `/usr/share/fonts` in the running StumpWM: it takes minutes and the desktop stops meanwhile. The size is `*vikix-font-size*` (11), settable in user.lisp before calling `(vikix-set-font)` again.
